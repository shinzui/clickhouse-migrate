# Bootstrap Seihou tooling and the four-package workspace

This ExecPlan is a living document. Keep Progress, Surprises & Discoveries, Decision Log, and Outcomes & Retrospective current. Distill durable decisions into `docs/adr/` before completion.


## Purpose / Big Picture


A contributor can enter a reproducible development shell, build all four libraries and run the same checks locally and in CI. The tooling is generated by Seihou's nix-haskell-flake template; the package layout leaves embedding, CLI integration and server test tools outside the core library dependency closure.

## Progress


- [x] M1 — 2026-10-16: Seihou 0.30.0 shell evaluates with the unchanged shipped lock; GHC reports 9.12.4. Formatting rejects a temporary malformed Haskell fixture (exit 1) and passes after its removal.
- [x] M2 — 2026-10-16: All four libraries build on aarch64-darwin; all four `cabal check` results are warning-free; all source distributions contain licenses and sources; the opt-in private driver builds. Local `nix flake check` passes all six checks. Linux validation is deferred at the user’s request; CI is configured but has not run remotely.

## Surprises & Discoveries


2026-10-16: The installed Seihou CLI accepts `seihou diff` without a module argument; the planned invocation was corrected. It reports no generated-file drift. The default-off driver flag needs an actual executable stanza for warning-free Cabal checks, so EP-1 supplies an explicitly failing bootstrap entry point for EP-4 to replace.

## Plan of Work


M1 applies the template with PostgreSQL, Redis and Kafka disabled, ClickHouse and process-compose enabled, formatting and hooks enabled, and the built-in single-package output disabled. Preserve `.seihou/config.dhall` and the existing manifest applications. Commit generated source and baseline metadata together. Put multi-package outputs and extra tools in the unmanaged `flake.module.nix`; do not hand-maintain a replacement generated flake. Stage new flake files before Nix evaluation so Git source filtering includes the shipped lock. GHC 9.12.4 is the inspected template's available default; use that baseline without claiming it is the newest compiler. Add a second compiler only after the template supports it and it passes the same checks.

M2 creates `cabal.project`, `clickhouse-migrate/clickhouse-migrate.cabal`, `clickhouse-migrate-embed/clickhouse-migrate-embed.cabal`, `clickhouse-migrate-cli/clickhouse-migrate-cli.cabal`, and `clickhouse-migrate-test-support/clickhouse-migrate-test-support.cabal`, each with package-local license and source distribution metadata. Create a small `clickhouse-migrate/src/ClickHouseMigrate/Prelude.hs` and compileable package entry modules without placeholder claims of migration functionality. Optional libraries may depend on core; core must not depend on them. Do not make core tests depend on test-support, which will depend on core and would create a package cycle; put server integration suites in test-support. Standardize test targets as `clickhouse-migrate-unit`, `clickhouse-migrate-embed-test`, `clickhouse-migrate-cli-test`, and `clickhouse-migrate-integration`, adding behavioral tests in their owning plans.

Wire each local package into one mutually recursive Haskell package set in `flake.module.nix`, with `packages.default` as core, named outputs for the four packages and checks for unit suites. Avoid a root callCabal2nix invocation against a nonexistent root cabal file. Add `justfile`, `.github/workflows/ci.yml`, and `README.md` documenting build, unit, integration and formatting entry points. Integration jobs are opt-in until the owned server fixture exists. `docs/dependencies.md` records actual dependency versions and evidence, not speculative bounds. Register the Jitsurei standard and concrete packages in `mori.dhall` using its existing schema after consulting Mori source if needed. Create the package-boundary/tooling ADR before marking M2 accepted.

Keep private core modules in `other-modules`, not `exposed-modules`. Reserve a manual, default-off Cabal flag `internal-test-driver` for a `clickhouse-migrate-test-driver` executable in the core package. EP-4 supplies its behavior using `src` plus `test-driver` sources and the same core dependency stanza; it must not depend on test-support or copy the implementation. Test-support's server suites launch the explicitly built driver as a subprocess and assert its structured result and proxy counts. Recipes pass the built executable path explicitly. This lets EP-4 and EP-5 test private transport/storage before the public runner exists, without exposing raw SQL/append operations or introducing a package cycle. Production outputs disable the flag; source distributions include the driver sources for opt-in qualification.

## Concrete Steps


Run this inspected invocation from the repository root, first with `--dry-run`, then without it:

```bash
seihou run nix-haskell-flake --var project.name=clickhouse-migrate --var 'project.description=Haskell migration toolkit for ClickHouse' --var ghc.version=ghc9124 --var nix.process-compose=true --var nix.postgresql=false --var nix.clickhouse=true --var nix.builtin-package=false --var nix.treefmt=true --var nix.pre-commit=true --no-save-prompted --dry-run
```

After creating the package wiring, stage only the scaffold's intended files and run:

```bash
git add flake.nix flake.lock nix flake.module.nix cabal.project clickhouse-migrate clickhouse-migrate-embed clickhouse-migrate-cli clickhouse-migrate-test-support
nix develop -c ghc --numeric-version
nix develop -c cabal build all
nix develop -c just check-packages
nix develop -c just test-unit
nix develop -c cabal sdist all
nix fmt -- --fail-on-change
nix flake check
seihou diff
```

Implement `just check-packages` to run `cabal check` from each package directory; implement `just test-unit` to select only non-server suites. Expect GHC 9.12.4 for the inspected generation, successful builds/checks and no edits proposed to managed template files. Record actual versions and any platform restrictions.

The package graph has no optional or test-support dependency reachable from the core library. Do not add a meaningless pass-only test merely to populate a suite. The template's developer server on default ports is a convenience; later fault tests must use isolated servers. Exercise the supported local platform. Linux execution is deferred per the user’s 2026-10-16 instruction; keep the CI definition ready and do not claim Linux qualification before it runs.

## Idempotence and Recovery


Preview Seihou changes before applying them. Repeating the same resolved template configuration should be conflict-free; inspect local edits rather than using `--force`. Keep template upgrades separate from ad hoc lock updates. Preserve unrelated working-tree changes and existing skill applications. Do not run broad Nix updates or start the shared developer ClickHouse service during build-only validation.
